# HHCC 2026 Prototype

This is the clean submission repository for the HHCC 2026 Prototype Development Track. It was initialized during the official hacking period and is intentionally separate from the team's research workspace.

## Current status

- Repository bootstrap only; there is no runnable prototype yet.
- The product direction and technical stack must be confirmed by the team before implementation begins.
- Every implemented capability must remain explainable, testable, and consistent with the final demonstration.

## Competition constraints

- Build the submitted project from scratch during the official hacking period.
- Do not copy a pre-event prototype into this repository.
- Record team responsibilities, technical decisions, and meaningful changes.
- Disclose AI tools and their actual purposes in [`AI_USAGE.md`](AI_USAGE.md).
- Record third-party code, models, data, fonts, and media in [`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md).
- Never commit credentials, personal information, or machine-specific configuration.

## Repository map

- [`AGENTS.md`](AGENTS.md): repository-wide operating and Git synchronization constraints for coding agents.
- [`docs/DECISIONS.md`](docs/DECISIONS.md): chronological technical and product decisions.
- [`docs/superpowers/specs/2026-08-22-repository-bootstrap-design.md`](docs/superpowers/specs/2026-08-22-repository-bootstrap-design.md): approved repository-bootstrap boundary.
- [`AI_USAGE.md`](AI_USAGE.md): transparent AI-use log.
- [`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md): dependency, model, data, and asset provenance.

Application source, tests, and demo assets will be added only after the product design is reviewed.

## Working agreement

1. Make one understandable change at a time.
2. Update the decision and disclosure records when a change affects them.
3. Run the relevant checks before committing.
4. Commit and push each coherent, verified milestone, and always synchronize before handoff, context switch, demonstration, or final submission.
5. Stage only explicit paths; do not automatically push every save or publish unverified half-complete work.
6. Keep the README's setup and demo instructions synchronized with the actual product.

## Running the project

There is no runnable application at this bootstrap stage. Setup, launch, test, and demo commands will be documented here as soon as the implementation stack is approved.
