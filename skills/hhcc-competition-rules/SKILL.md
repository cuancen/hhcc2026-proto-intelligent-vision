# HHCC 2026 比赛规则与提交纪律

> 工程架构规范见仓库根 `AGENTS.md`（零 DOM 内核、时间体系、容灾铁律等），本 skill 管比赛合规与提交纪律，二者冲突时以更严格者为准。

## 1. 赛事关键信息

- **赛程**：2026-08-21 20:00 → 2026-08-23 08:00（36 小时现场开发）
- **提交截止**：08-23 08:00 北京时间，预留 ≥20 分钟上传校验，严禁卡点
- **提交材料**（赛事官方平台）：项目名称；GitHub 公开仓库链接（全部代码）；≤3 分钟演示视频（**视频只传平台，绝不入仓库**）；项目概述文档；路演 PPT
- **路演**：10 分钟演示 + 1 分钟切设备 + 3 分钟 Q&A，超时即止；**只有现场实际展示的内容才计分**
- 仓库：`https://github.com/cuancen/hhcc2026-proto-intelligent-vision`

## 2. 作弊红线（违反 = 取消资格，绝对禁止）

1. **禁止带入赛前半成品**：所有代码必须在赛期内从零开发；禁止隐藏注释代码、隐藏模块冒充现场产出。
2. **禁止伪造提交时间**：不使用 `--date`、不改系统时间、不 rebase 改写已有提交的时间戳；**禁止空提交凑迭代数**（评委看得出无文件变更的提交）。
3. **禁止外部实时远程指导**：不允许微信/QQ 远程代写；允许查公开文档与开源教程，禁止抄袭。
4. **AI 使用必须透明**：AI 辅助允许，但团队必须能解释代码原理（`docs/AI使用声明.md` 的核对清单完成前，该文件不得随最终材料提交）；PPT/文档必须声明 AI 工具用途。

## 3. 评分导向（总分 100，决定开发优先级）

| 维度 | 分值 | 冲分策略 |
|---|---|---|
| 功能性与可用性 | **40（最重）** | 现场必须稳定跑通；交互流畅、场景适配、无障碍；任何新功能先保证不破坏现有稳定性 |
| 创意与原创性 | 20 | 机器视觉 × 座舱智能体 × L2 边界的跨学科叙事；避免复现现有方案的既视感 |
| 技术复杂度 | 20 | 真实 ML 本地推理、零 DOM 内核、纯函数指标管线、多源容灾——新功能延续此水准，拒绝玩具式堆砌 |
| 品牌与商业/社会影响 | 10 | 当前最弱项：logo/slogan/目标用户/疲劳驾驶社会价值数据/本地推理=隐私优势 |
| 团队协作 | 10 | 分工认领模块、Q&A 演练；文档中体现团队决策痕迹 |

**迭代次数由 Git commit 体现**：优秀档参考 24-30 次（创意/技术）、16-20 次（功能）。达标方式见下节。

## 4. Git 提交纪律

- **小步真实迭代**：一个功能拆 3-6 个 commit（参数设计 → 核心实现 → 测试 → 界面 → 文档），每个 message 说清"做了什么、为什么"
- **message 风格**：`类型(范围): 中文描述`，类型用 feat / fix / docs / chore / test / a11y
- **每次提交前**：`npm test` 全绿、`npm run build` 通过；改 `src/core/params.ts` 还须同步 `docs/PIPELINE.md` 并过一遍三场景
- 不提交：`node_modules/`、`env/`（PyTorch 环境）、`dist/`、`legacy/`、任何视频文件、密钥

## 5. 代码与文案规范（比赛视角）

1. **L2 术语规范**：全项目（代码注释、界面话术、文档、PPT）统一使用"L2 组合辅助驾驶"表述。
2. **隐私红线**：摄像头画面仅浏览器本地推理，零上传——新功能不得引入影像/数据外发路径；外部资源必须"失败零影响"（自托管 + 多源回退 + 模拟兜底）。
3. **新功能必须配套**：vitest 回归测试 + 《docs/功能说明.md》**末尾追加**新章节（只增不改旧内容）。
4. 无障碍不得回退：新增交互必须键盘可操作、带 aria 标注，尊重 prefers-reduced-motion。
5. 演示稳定性优先于功能数量：任何改动不得让 60 秒自动演示翻车。

## 6. 功能演示自动录制（团队要求）

每次新功能完成并验证通过后，**必须自主后台录制一段演示视频**作为团队素材：
- 工具：内置浏览器 `tab.recording` API（`actions` 脚本驱动点击/等待，fps 15，1280×720）
- 时长：单功能 15-30 秒（完整走一遍该功能的触发路径）
- 保存：仓库外 `D:\DPHarness\feature-recordings/`，命名 `日期_功能名.webm`
- ⚠️ 坑：`actions` 为空时录制立即结束，必须用 `{type:'wait', durationMs}` 撑时长
- 录制仅是内部素材，**绝不入 git 仓库**；最终 ≤3 分钟演示视频由团队据此剪辑后只传赛事平台

## 7. 上传/发布检查单

推送前逐项确认：☐ 测试与构建全绿 ☐ 未夹带 env/dist/视频/密钥 ☐ `docs/AI使用声明.md` 仅在核对清单完成后再推 ☐ message 符合风格 ☐ 提交时间真实（系统时间，无任何篡改）
